# vLLM Ascend 调测

当前以 PD 分离为打样范围，P 指 Prefill，D 指 Decode。目标是用可复核证据缩小问题范围，得到必要时可交接的复现与验证结果。

## 从现场推进

先看已有脚本、日志和环境，确认实际运行的版本、模型、角色及拓扑。脚本表示期望，进程参数、加载路径和运行日志证明实际状态；本地源码与部署代码分别记录。已有明确首错时围绕它追踪，不机械重跑一套全量检查。

围绕最后已证实的阶段与首个有因果意义的异常提出假设，选择最能区分假设的下一步。代码说明可能路径，现场因果还需请求身份、数据和时序对应。区分直接故障、级联现象和 PD 对触发/放大的影响。

执行进度与资源持有分别追踪：HTTP 接收、计算完成、KV 传输完成、完成通知和真正释放并非同一事件。证据缺失时保留未知，检查采集范围与日志级别，不用“没看到”代替“没发生”。跨端 ID 要映射，跨节点时钟未经校准时不用墙钟差直接计算阶段耗时。

寻找最小复现与定界相互推进：保留同一故障的判据，缩减无关条件，保存当前已验证的最小场景。一次未复现不能排除偶现问题。同步打印使故障消失时，考虑低扰动采证，并验证数据归属与采证本身的影响。

## 按需读取

根据当前不确定点选读；不要预读所有资料，也不要仅因“PD”就读完生命周期和全部案例。获得足够依据后继续分析或验证，允许改变方向。

| 当前需要解决的问题 | 读取 |
|---|---|
| 脚本、版本、实际加载或组网可能不匹配 | [现场基线](references/field-baseline.md) |
| 请求阶段、pull、delay free、DONE/ACK、取消或资源释放 | [PD 生命周期](references/pd-lifecycle.md) |
| 挂死、崩溃、通信失败，尚未找到首错或等待对象 | [功能定界](references/functional.md) |
| 乱码、重复、输出错误或评测精度变化 | [精度定界](references/accuracy.md) |
| TTFT、TPOT、吞吐、长尾或性能回退 | [性能定界](references/performance.md) |
| 构造、稳定或缩减复现，生成可交接复现包 | [最小复现](references/reproduction.md) |
| 同步打印掩盖问题，或需观察异步设备数据 | [异步采证](references/async-observation.md) |

资料中的符号是源码搜索入口，按现场 commit 核对分支、布局、参数和实际调用链，不能把示例实现当作所有 connector 的契约。

## 验证与交付

在用户授权范围内完成分析、采证和最小验证。沿用环境已有的远端、服务和 profiling 工具；工具不可用时使用已有材料继续定界，明确缺少哪项证据及如何获取。本包没有自动部署或 NPU 采证程序，不依赖某一私有工具或个人目录。

需要代码或插桩时按现场版本实现小范围、可回退的改动，并记录实验变量。设备相关验证在实际 Ascend 环境完成；静态分析、Mock 和文档检查各自只证明对应层面。不要用新加的同步、重算或重试偷偷改变原故障条件。

回复先给有边界的结论及关键证据，再给仍未排除的假设和最有价值的下一步。执行过实验则提供实际命令、配置差异、结果和证据位置；没有运行则明确是方案。内容随问题规模变化，不强制套完整报告。

反复因缺少阶段、身份或数据证据而无法定界时，提出对应的 DFX 补强候选及验收方式；先查现有能力，未经用户批准不写入正式需求池或覆盖映射。
