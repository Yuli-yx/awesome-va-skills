# 精度与输出异常定界

用于乱码、重复、空输出、答案错误或评测下降。先确定错误发生在输入、生成、状态/KV、输出传输还是评分边界。

## 定义可比较对象

保存故障样本的原始输入或可复现 token、模型/tokenizer/模板、生成参数、输出长度及结束原因。涉及敏感输入时遵从现场数据范围，不默认把完整 prompt 和 KV 导出。

区别“协议解析失败”“token 序列异常”“输出被截断”“答案不正确”“评分提取失败”。任务返回 success 只表示对应层成功；无异常文本也可能精度错误。

可使用确定性配置辅助定位首次分歧，但记录与原配置的差异。固定 seed 不保证不同并行、量化或数值实现逐 token 一致；随机生成需要匹配的多次对照与逐样本失败模式，不能仅看总分。

## 由外向内定位分歧边界

| 已有证据 | 下一步候选 |
|---|---|
| HTTP chunk/parser 错误 | 保存该连接应用错误及双端同一流 payload，核对重传/缺口；定位字节改变在哪两个观察点之间 |
| 输出合法但答案不符 | 对齐样本、答案提取、长度和终止；比较基线输出的首次分歧，而非合并为“网络乱码” |
| PD 异常、直发正常 | 核对两组实际算子/调度路径和输入；沿交接 metadata、接收结果和消费位置继续缩小 |
| 某层/位置状态异常 | 对齐逻辑 token、KV group、dtype、有效范围与布局后采样；查看位置索引和 block/slot 来源 |
| 同步打印后不复现 | 读取 [异步采证](async-observation.md)，保持原现场并比较采证扰动 |

按假设选择 direct-P、direct-D、full-PD 对照，不要求每次跑完三组；如果直发改变了完整 prefill、缓存或采样路径，解释这些差异。传输前已异常能缩小责任范围，但某一步没有活跃传输不能单独排除先前 KV 输入影响。

## KV 与异步状态

查当前模型的 KV spec、group、逻辑 block 与 kernel block 映射、有效 token 长度、position/slot mapping、Mamba 或压缩/量化状态以及 spec decode 计数。不要把普通 K/V 的 shape 假设套到所有模型。

对比 P 交接范围、D 本地分配、传输范围与实际消费范围。相同均值/方差不证明数据相等；跨布局原始内存 hash 没有直接可比性；比较时先映射到相同逻辑数据。有效范围之外的 padding 或未初始化值不应混入正常样本。

对非法索引追其生产者：scheduler token 数、有效上下文、draft/rejected 数与异步 discard。校验算子报错可能只是发现坏输入。代码上能够逐值重建故障输入，是强证据，但仍注明是否完成了真实运行验证。

## 复现与验证

转读 [最小复现](reproduction.md)，从错误样本、必要前置请求或状态序列缩减。修复后复核同样本及原始生成配置，保留输出、错误类型和结束原因；不要只以总分回升判定传输、状态和协议问题均已消失。
