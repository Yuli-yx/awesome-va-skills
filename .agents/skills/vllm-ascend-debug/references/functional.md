# 功能故障定界

用于挂死、退出、请求失败与资源异常。目标是找到首个有效故障或明确的等待关系，不按最终错误码自动归责。

## 从可见症状找缺失的推进条件

| 现场 | 优先追踪 |
|---|---|
| 进程已退出 | 首个异常/信号、worker/plog、退出前调度和设备任务；把后续断连单独标记 |
| 进程在但请求不动 | 队列、线程栈、等待事件/锁、请求阶段与预期对端动作；区分慢与无进展 |
| API 正常但传输失败 | 控制面和数据面分别对照，找到具体 peer、rank、连接或 transfer |
| 只在并发下失败 | 共享对象、buffer 复用、异步输出、抢占、资源压力和时序 |
| 资源迟迟未释放 | 进入保留状态的原因及完成链，转读 [生命周期](pd-lifecycle.md) |

拿到多端日志后保留首错前窗口和后续链路，不只截取 ERROR 行。设备异步错误可能在 synchronize 或下一次调用处暴露，沿已失败任务和其输入回溯；plog 与应用日志按进程/设备/任务对应。

HIXL/Mooncake 的上层失败、通道不可用和对端连接断开都可能是后果。围绕首个传输失败追两侧建链、任务、重试/资源证据；有可用的 HIXL 专项工具时按范围复用。不要仅凭某错误码认定 PFC、网卡或 HIXL 本身有缺陷。

## 选取有区分力的对照

根据假设选择旁路 proxy、直发 P/D、特定卡对、单/多请求或特性开关。每个对照说明改变了哪些条件，以及成功/失败分别支持什么。直发 D 可能改为完整本地 prefill，不是等价 PD workload；裸通信通过也不证明服务态传输正常。

小卡对矩阵可帮助区分 P、D 和路径：失败 P 对多个 D、健康 P 对同一 D 的结果比重复测同一卡对更有用。卡数缩减也会改变并行和设备映射，要核对实际 endpoint。

当控制某个事件顺序能复现故障时，转读 [最小复现](reproduction.md)；当插桩改变复现概率时，转读 [异步采证](async-observation.md)。不要先全局关闭异步、增加重试或延长超时来替代定位。

## 闭环标准

按用户问题交付直接根因或有证据的范围；无法闭环时，明确还缺哪条关联、哪个边界输入或哪个对照。修复验证既检查原故障，也检查异常请求终结与资源释放；HTTP 成功、无报错或短时间不卡均不能单独证明闭环。
