# 性能异常定界

用于 TTFT、TPOT、吞吐、长尾或回退。先确定用户关注的是单请求时延、固定并发吞吐、服务容量还是传输本身。

## 先判断比较是否成立

对齐实际版本/patch、模型量化、硬件与拓扑、启动参数、输入/输出长度分布、缓存冷热和命中、并发或到达率、样本数、预热/稳态/排空窗口。检查失败、超时、重试和输出被截短是否进入统计。

不要将服务 E2E 输出吞吐称为纯 decode 吞吐，也不要把两个 E2E 平均值之差全部解释成 KV 传输时间。指标定义随 benchmark 工具变化，先查结果文件与命令。

## 按证据拆开时间与容量

可能的阶段包括：proxy/准入排队、P 排队与 prefill、交接与 D 准入、metadata/建链、KV 搬运及转换、D 调度、decode、HTTP 输出。阶段可能重叠，不直接相加聚合均值；优先关联同请求时间线，并注明未校准的跨机时间边界。

固定并发闭环中，请求耗时变长会更久占用槽位；稳定且口径一致时，完成速率约为平均在途请求数除以平均端到端耗时。平均在途数不一定等于配置并发，尤其在短测试启动/排空阶段。

高 prefix 命中、短输出可能让交接成本更突出，但不能据此断言 PD 在所有负载下峰值更低。固定到达率、固定并发和充分饱和时测到的是不同问题。用匹配负载和资源预算的对照说明结论范围。

## 选择下一步实验

| 怀疑 | 能区分原因的证据/实验 |
|---|---|
| 新配置造成回退 | 同版本、同架构、同 workload 的开关对照；先查回退是否在该变更前已存在 |
| 建链/metadata 耗时 | 区分首请求与连接复用、排队与实际处理、各次重试 |
| KV 传输带宽/拥塞 | 实际字节数、传输区间、重试、两侧通信日志和共享路径；配置生效日志不证明调度收益 |
| 卡或 rank 不均衡 | 同 step 的各 rank 时间线与负载；先核对拓扑与背景资源占用 |
| 计算/同步气泡 | 有具体目标后采 profiling，区分设备执行、主机提交和等待 |
| 只有长压后退化 | 保留资源积累、缓存和请求历史，按 [最小复现](reproduction.md) 缩减 |

可复用环境中的 serving/benchmark/profiling 能力；没有工具时先分析已有结果，给出匹配现场的命令方案。采 profiling 或详细日志本身可能改变吞吐，需记录开销并保留不开采证的结果。

## 交付

说明比较组、统计口径、差异和瓶颈证据，区分架构解释、相关性与受控实验支持的因果。保留原始结果与启动/负载命令。样本不足时给出下一步采样方案，不把一次均值变化解释成稳定收益。
