# 寻找最小复现场景

用于建立、稳定、缩减复现或交接给他人验证。追求保留同一故障、资源和时间成本足够低的已验证场景，不承诺全局最小。

## 保留可回退的基线与故障判据

保存原始版本、配置、脚本、输入/请求序列及初始状态。判据使用失败阶段、首错位置、关键状态/数据关系或可比较的退化指标；相同上层 timeout 不足以证明是同一故障。根因尚未明确时，写出当前如何判定一致及可能的歧义。

原现场不可得时可根据代码和日志构建机制复现，说明它与原场景的对应证据。机制重建、Mock 回归、真实设备最小复现和完整现场复现分别标注，不互相替代。

## 选择缩减维度

| 维度 | 可尝试 | 核对是否丢失必要条件 |
|---|---|---|
| 请求/输入 | 数据集→故障样本或短序列，减少 token/输出长度 | 长度边界、前置请求、缓存状态、取消时机 |
| 压力/时长 | 减少并发、轮次或预热 | 异步重叠、抢占、内存压力、连接/资源累积 |
| 部署 | 多实例→特定 P/D，旁路 proxy/pool | 路由、字段、重试、传输和计算路径是否改变 |
| 拓扑/特性 | 减少 rank、卡数，去除无关特性 | DP/TP/PP 语义、设备映射、跨机、Graph/async 是否是触发条件 |
| 模型/数据 | 小型同构模型、少量层、合成输入 | KV spec/layout、算子分支、dtype、资源压力是否仍一致 |
| 执行层 | 完整服务→协议/connector→函数或算子 | 调用顺序、边界输入、资源所有权与并发关系是否对应 |

按假设使用单变量、分组、二分或组合缩减，不规定顺序。故障消失时回退到最近可复现版本，检查被去除条件及交互。某开关关闭后正常只说明条件改变，不能直接认定该特性实现有错。

时序问题可在明确的生命周期边界控制暂停、取消或事件顺序以替代盲目长压；记录插桩带来的新顺序，证明它与原机制对应。同步打印掩盖问题时，参考 [异步采证](async-observation.md)。

## 不同问题的保留条件

- 功能：保留同一首错/等待关系。并发问题的最小场景可以仍需要多个请求、rank 或长时间预热。
- 精度：保留故障样本、必要上下文、状态历史和可比较的生成配置；以首次分歧或同类错误作为判据。
- 性能：保留触发瓶颈的负载、缓存和稳态窗口；空载单请求不能替代拥塞复现。

每次实验记录改变的条件、初始/重置状态、尝试次数、失败次数、每轮时长或请求量、关键证据。未复现、观察不足、环境失效和出现不同错误分别标记。一次未复现不排除偶现原因。

## 可交接的产物

按现场需要生成启动与触发脚本、最少输入、版本/配置、预期与实际表现、成功复现判据、关键日志、频率记录，以及原现场到当前场景的差异。说明所需 NPU、模型/数据获取条件；不打包凭据或默认可共享的完整私有数据。

脚本应记录自身失败并限制等待/重试，避免无止境压测。复现次数和时长依据历史失败分布与资源预算选择，不写死“跑一次通过”或固定分钟数。

继续缩减不能保留故障、成本明显超过收益或已足够验证修复时，交付当前最小场景和停止理由。修复后先验证该场景，再在条件允许时回到原现场或代表性端到端负载；仅生成脚本不算复现完成。
